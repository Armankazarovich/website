# ARAY Production — архитектурные автоматизации, которые нас спасают

Дата: 2026-04-30

## Цель

Сделать так, чтобы проект рос быстро, но не превращался в хаос.

Автоматизация нужна не ради “техники ради техники”, а чтобы:

- не забывать маршруты;
- не ломать роли;
- не дублировать меню;
- быстрее запускать новые ниши;
- безопасно подключать интеграции;
- проверять мобильную/PWA-версию;
- сохранять единый стиль.

## 1. Admin Route Audit

Автоматическая проверка:

- все `href` из навигации существуют;
- все header actions ведут на существующие страницы;
- все quick actions существуют;
- нет ссылок на удаленные/устаревшие маршруты;
- неизвестные внешние ссылки явно помечены как external.

Первый найденный пример: `/admin/products/new` упоминается в хедере, но страницы сейчас нет.

## 2. Admin Registry

Единый реестр разделов админки:

- id;
- route;
- title;
- subtitle;
- icon;
- group;
- roles;
- permission section;
- header actions;
- search keywords;
- mobile behavior;
- ARAY intents.

Из него должны питаться:

- боковое меню;
- мобильное меню;
- поиск;
- заголовки;
- права;
- кнопки хедера;
- будущая документация;
- подсказки ARAY.

## 3. Permission Matrix Test

Автоматически проверять:

- роль видит только свои разделы;
- роль не получает доступ к запрещенному URL;
- nav и `AccessGuard` не расходятся;
- медиа-права соответствуют общей матрице;
- SUPER_ADMIN и ADMIN видят все нужное.

## 4. Media Asset Registry

Постепенно перейти от “сканируем папки” к единой базе медиа:

- `MediaAsset`;
- тип: image/video/document/background/icon/logo;
- папка/путь;
- alt;
- tags;
- usage;
- tenant/project;
- uploaded/generated/imported;
- optimized variants;
- права удаления/редактирования.

Это важно для каталога, фонов, брендов, ARAY, будущих клиентов и SEO.

## 5. Design Token Guard

Проверять, что новые разделы используют единый стиль:

- цвета через токены;
- поверхности через admin kit;
- кнопки через общий компонент;
- таблицы через общий компонент;
- popup/sheet через общий компонент;
- нет случайных inline-стилей без причины;
- нет старых классов, которые конфликтуют с новым стилем.

## 6. PWA/Mobile Audit

Автоматический/полуавтоматический чек:

- mobile viewport;
- tablet viewport;
- desktop viewport;
- safe-area;
- theme-color;
- install prompt;
- standalone PWA;
- bottom nav;
- rail hidden on mobile;
- клики без hover;
- клавиатура не перекрывает input.

## 7. Performance Budget

Проверки:

- тяжелые компоненты грузятся отложенно;
- фоновые изображения локальные WebP;
- видео не включаются без необходимости;
- таблицы не рендерят лишнее;
- картинки имеют размеры;
- не добавляются тяжелые библиотеки без причины.

## 8. ARAY Action Map

Для каждого раздела хранить:

- что ARAY может открыть;
- что ARAY может объяснить;
- что ARAY может выполнить;
- что ARAY должен только подготовить;
- что требует действия пользователя во внешнем сервисе;
- какие ограничения нужно проговаривать.

## 9. Client/Niche Blueprint

Для каждого будущего проекта:

- PiloRus;
- Zaidr/Zeder;
- тара/коробки;
- другие сферы;

должен быть blueprint:

- ниша;
- публичный сайт;
- каталог/услуги;
- CRM;
- ERP;
- роли;
- документы;
- интеграции;
- PWA;
- ARAY контекст;
- публичная демонстрация.

## Ближайшая автоматизация

Начать с самого дешевого и полезного:

1. Скрипт проверки admin routes.
2. Документ missing routes.
3. Затем `admin-registry` как кодовый источник правды.

Это снизит риск поломок при каждом новом разделе.
