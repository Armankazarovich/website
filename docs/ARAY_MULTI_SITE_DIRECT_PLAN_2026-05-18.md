# ARAY: Direct сейчас и мультисайтовая CMS

Дата: 18.05.2026  
Эталон: PiloRus  
Цель: запускать рекламу и сайты быстро, но без дублей, смешивания данных и слива бюджета.

## 1. PiloRus Direct: текущий статус

Проверено через админку и внутренний Direct API:

- Direct подключен через OAuth token.
- Публичный домен для объявлений: `https://pilo-rus.ru`.
- Регион Direct: `1` (Москва и Московская область).
- Счетчик Метрики сохранен: `108430589`.
- В Direct уже есть кампания:
  - ID: `709207003`
  - Название: `Пилорус каталог`
  - Состояние: `ON`
  - Статус: `ACCEPTED`
  - Тип: `TEXT_CAMPAIGN`
  - Дата старта: `2026-04-20`

Вывод: PiloRus Direct уже находится в боевом состоянии. Сейчас нельзя бездумно создавать вторую кампанию поверх первой: это может размазать статистику и дать лишние расходы. Правильный следующий шаг - проверить в кабинете Direct бюджет, показы, ставки, минус-слова и цели Метрики.

## 2. Безопасный рекламный принцип ARAY

ARAY не должен включать деньги автоматически.

Правильная логика:

1. Собрать кампанию из каталога.
2. Проверить домен, товары, цены, наличие, регион, UTM, Метрику.
3. Создать черновик/остановленную кампанию.
4. Показать владельцу ссылку на Direct.
5. Включение бюджета - только вручную владельцем в кабинете Direct.

Для PiloRus сегодня важнее не новый черновик, а контроль уже активной кампании.

## 3. Что закрыть по Direct перед масштабированием

- Добавить цели Метрики: заказ/заявка, телефон, мессенджер, корзина, checkout, вовлеченная сессия.
- В админке явно показывать: “кампания уже активна”, чтобы случайно не создать дубль.
- В выгрузке Direct держать защиту от повторной кампании без отдельного подтверждения.
- В аналитике связать расходы Direct с заказами, лидами и звонками.
- Для каждого сайта хранить свои токены, счетчики, регионы, домены и кампании.

## 4. Видение CMS: одна система, 1000 сайтов

ARAY должен стать не “одним сайтом PiloRus”, а платформой:

- ARAY Production - главный кабинет владельца платформы.
- Мои сайты - наши собственные проекты.
- Сайты клиентов - проекты клиентов.
- Один код и одна админка.
- У каждого сайта свои данные: товары, заказы, клиенты, CRM, реклама, аналитика, финансы, задачи, документы, уведомления.
- PiloRus остается эталоном для пиломатериалов.
- Стройматериалы становятся первым проверочным клоном.

## 5. Как должен создаваться новый сайт

Идеальный поток:

1. Нажать “Создать сайт”.
2. Выбрать сферу: пиломатериалы, стройматериалы, мебель, услуги, локальный магазин.
3. Заполнить короткий бриф: название, город, телефоны, мессенджеры, график, доставка, юридические данные.
4. Загрузить логотип или брендбук.
5. Загрузить прайс/таблицу товаров.
6. ARAY собирает структуру сайта: каталог, категории, карточки, тексты, SEO, фильтры.
7. Сначала сайт открывается на техническом домене: например `client.aray.online`.
8. Потом подключается свой домен через DNS.
9. После проверки включаются Метрика, Direct, CRM, отчеты и уведомления.

## 6. Доменная логика

Для старта:

- Технические домены: `slug.aray.online`.
- Клиентские домены: через A-запись на сервер или через CNAME, если провайдер и инфраструктура позволяют.
- До публикации домен должен пройти проверку: открывается сайт, есть SSL, корректный tenant, корректные sitemap/robots.

На текущем этапе уже добавлена карта доменов через `TENANT_DOMAIN_MAP`. Это хорошо для первых проектов. Для 1000 сайтов нужна база доменов и безопасный edge/cache-слой, чтобы middleware быстро понимал, чей это сайт.

## 7. Текущий фундамент в проекте

Уже хорошо:

- В большинстве таблиц есть `tenantId`.
- Есть модель `Tenant`.
- Есть middleware, который определяет tenant по домену.
- Есть helper для текущего tenant.
- Direct и Metrika уже начали читать настройки tenant.
- PiloRus можно использовать как эталонную нишу.

Нужно довести:

- `SiteSettings` сейчас имеет глобальный `key @unique`; для 1000 сайтов нужен уникальный ключ внутри tenant: `tenantId + key`.
- У части сущностей уникальность пока глобальная: slug товара, slug категории, email подписчика, промокод. Для разных сайтов это должно быть уникально внутри tenant.
- Фильтр tenant включать только после аудита запросов, иначе есть риск смешать или скрыть данные.
- Нужен экран “Мои сайты / Сайты клиентов”.
- Нужен мастер создания сайта.
- Нужен импорт прайса в tenant, а не в общий каталог.
- Нужна проверка прав пользователей по tenant и роли.

## 8. Роли пользователей

Минимальный набор:

- Platform Owner - владелец ARAY Production, видит все сайты.
- Agency Admin - управляет сайтами клиентов.
- Business Owner - владелец конкретного бизнеса.
- Manager - заказы, лиды, звонки.
- Warehouse - сборка, остатки, отгрузка.
- Courier - доставка.
- Accountant - оплаты, финансы, документы.
- Marketer - Direct, SEO, акции, аналитика.
- Viewer - только просмотр.

Каждый пользователь должен иметь доступ только к своим tenant/site, кроме владельца платформы.

## 9. Что делать на примере стройматериалов

Стройматериалы не делаем “с нуля”. Делаем как клон эталона:

1. Создать tenant `stroymaterialy`.
2. Подключить домен или временный поддомен.
3. Загрузить брендбук/логотип.
4. Импортировать прайс.
5. Выбрать шаблон “Стройматериалы”.
6. Сгенерировать категории, карточки, SEO-описания, фильтры.
7. Проверить мобильную витрину и корзину.
8. Подключить Метрику.
9. Подготовить Direct черновиком.
10. Включить рекламу только после ручной проверки.

Завтра:

Главный принцип: PiloRus - эталон, ARAY - фабрика сайтов, каждый клиент - отдельный tenant с чистыми данными.
