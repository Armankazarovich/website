# PiloRus Stories Media Pipeline — дизайн модуля 0.10.0

## Решение

`marketing.store-stories` получает встроенный конвейер подготовки видео. Менеджер по-прежнему загружает файл в редакторе сторис, но публичная сторис получает только проверенную web-копию. Исходник сохраняется и остаётся маршрутом отката.

Реализация выпускается сначала как PiloRus client candidate. Она описывается нейтральным контрактом, но не копируется в Zeder, ARAY Production или другие проекты до отдельной совместимости, канарейки и утверждения.

## Пользовательская задача

- Менеджер загружает записанную презентацию, обзор, отзыв или LIVE-карточку без ручного сжатия.
- Сайт сам подготавливает видео для мобильной сети.
- Менеджер видит честные состояния: загрузка, очередь, обработка, готово, ошибка и повтор.
- Посетитель не получает исходный файл весом в сотни мегабайт.
- При любой ошибке опубликованная версия и исходник не теряются.

## Границы

- Канонический проект: `D:\проект\pilorus\website`.
- Релизный кандидат: `D:\проект\pilorus\worktree-stories-media-patch`.
- Экран: `/admin/stories`.
- Публичные потребители: Stories widget и `/stories`.
- Другие страницы, каталог, заказы, цены, остатки, связи сторис, CTA и счётчики просмотров не меняются.
- Prisma-схема не меняется в 0.10.0: очередь хранится отдельно от бизнес-данных.
- Исходные видео не удаляются и не перезаписываются.

## Архитектура

### 1. Политика подготовки

Чистый модуль определяет, требуется ли преобразование, строит параметры FFmpeg и проверяет результат. MP4 до 24 MiB может быть принят без повторного кодирования. MOV, WebM и MP4 свыше 24 MiB проходят преобразование.

Web-профиль:

- MP4;
- H.264, `yuv420p`;
- AAC 96 kbit/s;
- до 30 кадров/с;
- ограничение 720×1280 без увеличения исходника;
- CRF 23, maxrate 4 Mbit/s, bufsize 8 Mbit/s;
- ключевой кадр примерно раз в 2 секунды;
- один поток кодирования, чтобы не перегружать VPS;
- `faststart`, чтобы индекс MP4 находился в начале файла.

### 2. Артефакты

- Исходник: `public/images/stories/originals/<upload-id>.<ext>`.
- Временный результат: `public/images/stories/<upload-id>.processing.mp4`.
- Публичная копия: `public/images/stories/<upload-id>-web.mp4`.
- Автообложка: `public/images/stories/<upload-id>-poster.jpg`.
- Состояние и откат: `.story-media-jobs/<job-id>.json`, вне публичного URL.

Публичная копия и обложка появляются только атомарным переименованием после проверки. Частично записанный файл никогда не становится `mediaUrl`.

### 3. Очередь и восстановление

Обработка запускается отдельным Node-процессом и не зависит от времени HTTP-запроса. Глобальная блокировка допускает только одно кодирование одновременно. Другие задания остаются в очереди. Зависшее задание можно безопасно повторить; завершённое задание идемпотентно возвращает существующий результат.

Состояния: `QUEUED`, `PROCESSING`, `PUBLISHING`, `READY`, `FAILED`.

Ошибка содержит короткий безопасный текст для менеджера; командная строка, серверные пути и секреты в API не возвращаются.

### 4. Новая загрузка

Прямой и частичный загрузчики используют общий конвейер. Клиент получает `jobId`, опрашивает защищённый status API и применяет в форму только `READY.url`. Автообложка заполняется только если менеджер ещё не выбрал свою.

Если обработка не удалась, исходник остаётся, форма не получает тяжёлый публичный URL, а менеджеру предлагается повторить.

### 5. Действующая сторис и канарейка

На карточке локального VIDEO/LIVE появляется действие «Подготовить видео». Сервер берёт текущий `mediaUrl`, создаёт web-копию и после проверки условно меняет только `StoreStory.mediaUrl`, если сторис всё ещё указывает на прежний URL.

До изменения записывается rollback receipt с `storyId`, tenant, старым и новым URL. Действие «Вернуть оригинал» выполняет обратное условное изменение. Заголовок, связи, CTA, порядок, активность, просмотры и обложка не меняются.

Первая канарейка выполняется только для одного из двух подтверждённых тяжёлых роликов. Второй остаётся контрольным до прохождения живого браузера.

### 6. Поставка FFmpeg

FFmpeg и FFprobe поставляются как зафиксированные npm-зависимости внутри Linux release artifact. Модуль не зависит от ручной установки пакета на VPS и не ослабляет проверку SSH-ключа.

### 7. Тексты

- «Загружаем исходник…»
- «Видео в очереди. Оригинал сохранён.»
- «Подготавливаем видео для сайта…»
- «Видео готово для сайта.»
- «Не удалось подготовить видео. Оригинал сохранён.»
- Действия: «Повторить», «Подготовить видео», «Вернуть оригинал».

LIVE описывается честно: в 0.10.0 это закреплённая видеопрезентация онлайн-продавца; настоящий прямой эфир является отдельным будущим провайдером и не имитируется.

## Безопасность

- Все API требуют существующее staff/manager разрешение загрузки или управления сторис.
- `jobId`, расширение и локальный media URL проходят allowlist-проверку.
- Рабочие пути разрешаются только внутри папок модуля.
- Публикация использует условное обновление по `id + tenantId + прежний mediaUrl`.
- Внешние URL не скачиваются и не преобразуются.
- Исходник не удаляется автоматически.
- Повтор не создаёт параллельную публикацию одного задания.

## Проверка и критерии готовности

1. Чистые тесты политики: решение о преобразовании, параметры кодека, безопасные пути, валидация результата.
2. Интеграционный тест на реальном FFmpeg создаёт вертикальный ролик, обрабатывает его и проверяет H.264/AAC, размер, разрешение, web URL и сохранённый исходник.
3. Ошибка FFmpeg оставляет исходник и возвращает `FAILED` без публичного `.processing` файла.
4. `stories:check`, TypeScript, release/protection gates и production build проходят на финальном hash.
5. Реальный браузер проверяет desktop/tablet/mobile, загрузку, очередь, готовность, ошибку/повтор, отсутствие тяжёлого GET в закрытом виджете, 206 и воспроизведение открытой сторис.
6. Канарейка уменьшает один живой ролик минимум в 5 раз, не меняет остальные поля сторис и имеет проверенный возврат к исходному URL.
7. Живой сайт, каталог, `/stories`, `/admin/stories` и `/api/health` доступны после релиза; консоль и сеть не содержат новых ошибок.

## Версия и продвижение

- `0.10.0-beta.1`: локальный кандидат и браузерная проверка.
- `0.10.0-rc.1`: одна живая канарейка и проверенный rollback.
- `1.0.0`: обе тяжёлые сторис переведены на web-копии, будущая загрузка подтверждена менеджерским сценарием, паспорт и Drift Lock зелёные.
