## Дизайн-курс админки

Цель: админка должна ощущаться как дорогое PWA-приложение будущего, а не обычный сайт.

Базовые принципы:

- Единый дизайн-пакет для админки, отдельно позже будет пакет для публичного сайта.
- Минимализм, дорогая тишина, высокая читаемость.
- Стекло должно быть размытым и чистым, без грязных фонов и без потери контраста.
- Анимации редкие, полезные, плавные. Не перегружать систему.
- Иконки должны быть единым языком: понятные, минимальные, без визуального шума.
- Цветовые темы: в будущем 9 осмысленных палитр под разные типы людей/настроения/бизнесы.
- Темная и светлая версии должны быть полноценными, включая PWA/status bar на iPhone.
- В светлой теме не должно быть лишней цветной грязи. Больше чистого стекла, воздуха и читаемости.
- В темной теме можно глубже: природа, горы, лес, вода, водопады, световые акценты.
- Фоны должны быть универсальные, не только пиломатериалы: ARAY — будущая платформа для всех ниш.
- Главный живой источник фото-фонов для единой админки ARAY: `D:\ARAY PRODUCTION\ФОН ДЛЯ ПЛАТФОРМЫ`.
- Арман будет обновлять фото именно в этой папке. При подборе новых фонов сначала смотреть туда, а не в случайные внешние источники.
- В сайт/прод нельзя ссылаться напрямую на `D:\...`: выбранные фото нужно копировать/сжимать в `public/images/admin-atmosphere/` и подключать уже оттуда.
- Цель по оформлению: 9 палитр интерфейса + 9 фото-атмосфер только для админки, чтобы единая админка выглядела мощно, современно, функционально и из будущего.

## Меню и навигация

## Дизайн-система ARAY

- Актуальные правила визуального стиля, палитр, иконок, фото-фонов, карточек оформления, отступов, движения и применения ко всей экосистеме: `docs/aray-design-system-rules-2026-05-01.md`
- Законы автоматизации проекта: `docs/aray-automation-laws-2026-05-01.md`
- Главный принцип: каждый отступ, шрифт, цвет, иконка и элемент должны быть осознанными и работать на единый характер ARAY.
- Цветовая атмосфера применяется ко всей экосистеме: админка, ПилоРус, будущие клиентские сайты, попапы, мобильные меню, конструктор, CRM/ERP, финансы, кошелек, маркетинг, интеграции.
- Фото-атмосферы остаются уникальной фичей админки; публичным клиентским сайтам подбирать или генерировать визуалы под их сферу.
- Иконки по умолчанию не должны быть разноцветными: использовать токены из `lib/aray-design-tokens.ts`, а warning/success/danger применять только когда цвет реально сообщает статус.
- Палитры считать набором “8 характеров + фирменный ARAY”. 9-я палитра `ARAY` — глубокий графитово-синий фундамент, золотой акцент, вода + золото + интеллект.
- Hover/блеск — фирменный почерк ARAY: `admin-liquid-surface` + `admin-liquid-interactive`, мягкий primary-glow, легкий border-orbit, без дешевого неона и без постоянного свечения всех элементов. Использовать токены `ARAY_LIQUID_SURFACE`, `ARAY_LIQUID_INTERACTIVE`, `ARAY_SHIMMER_TRACE`, `ARAY_ICON_HOVER_LIFT`.
- Адаптивность — обязательная часть продукта: сразу проверять mobile, tablet, desktop, большие сенсорные мониторы, кассы, телевизоры и PWA. Touch-цели держать не меньше 44px, панели и попапы делать со scroll-зонами внутри viewport.
- PWA/APK не должны быть одними для всех: админка ARAY, клиентские сайты и ролевые приложения могут иметь свои manifest, logo, favicon, icons, start_url, scope, права и сценарии. У клиентов главный знак — их бренд, не наш.
- Для ролей заранее продумать отдельные входы/приложения: владелец, менеджер, курьер, официант, склад, касса, водитель, исполнитель, партнер. Для автомобиля/Android-магнитолы нужен безопасный voice-first режим ARAY: крупные карточки, минимум касаний, выручка/товары/статусы голосом.
- Роли, доступы и уведомления — отдельная системная фича. Нужна единая матрица: кто что видит, кто что может делать, кто какие события получает, через какой канал, с каким уровнем важности и почему.
- Уведомления не должны шуметь: critical/action/info/history, quiet hours, группировка повторов, журнал доставки, role-based каналы, объяснение через ARAY.
- Главный закон автоматизации: если решение повторится больше двух раз, оно должно стать системой — токеном, компонентом, матрицей, шаблоном, проверкой, генератором или документированным правилом.
- Следующие системные матрицы для будущих проходов: role-permission matrix, notification event registry, PWA manifest generator по tenant/role, design token/component checklist, responsive + PWA QA checklist, asset pipeline checklist, ARAY AI action safety matrix.
