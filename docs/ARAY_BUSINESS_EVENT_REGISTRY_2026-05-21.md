# ARAY Business Event Registry

Дата фиксации: 2026-05-21

Статус: первый рабочий слой для ARAY Business Automation Director.

## Суть

ARAY должен видеть бизнес не как набор страниц, а как поток событий. Событие - это сигнал, после которого нужен следующий полезный шаг.

Примеры:

- клиент задал вопрос в сторис;
- пришел новый заказ;
- появился лид;
- нужен документ;
- нужна доставка;
- корзина брошена;
- отзыв ждет модерации;
- задача просрочена;
- оплата ожидает проверки;
- остаток товара низкий.

## Первый Кодовый Слой

Источник: `lib/aray-business-events.ts`.

Этот слой пока не меняет структуру базы. Он переводит событие в понятный план:

- тип события;
- источник;
- приоритет;
- режим: директор, клиент или смешанный;
- ниша бизнеса;
- краткое объяснение для директора;
- краткое объяснение для клиента;
- рекомендуемые действия;
- где нужно подтверждение человека.

## Уже Подключено

### Сторис

Файл: `app/api/stories/[id]/message/route.ts`.

Когда человек пишет вопрос, комментарий, отзыв или предложение из сторис, ARAY:

- определяет тип бизнес-события;
- добавляет план действий в CRM-контекст;
- кладет событие в metadata задачи;
- возвращает событие в ответ API для будущего интерфейса;
- оставляет закон подтверждения для ответа, публикации и важных действий.

### Новый Заказ

Файл: `app/api/orders/route.ts`.

Когда создается заказ, ARAY:

- создает событие `order.created`;
- формирует план директора: проверить заказ, контакт, доставку и документы;
- добавляет событие в историю клиента, если есть пользователь;
- передает событие в workflow payload;
- добавляет заметку в CRM-лид, созданный из заказа.

## Закон Подтверждения

ARAY может сам:

- собрать контекст;
- предложить действие;
- подготовить черновик;
- записать внутреннюю заметку;
- передать событие workflow-слою.

ARAY не должен без подтверждения:

- отправлять сообщение клиенту;
- менять данные;
- публиковать отзыв или заявку;
- запускать рекламу;
- передавать персональные данные курьеру, партнеру или подрядчику;
- отправлять документ;
- делать платежное действие.

## Следующий Шаг

1. Сделать единый журнал событий в админке.
2. Добавить фильтры: срочно, продажи, доставка, документы, отзывы, задачи.
3. Дать ARAY кнопку "что делать дальше" по каждому событию.
4. Подключить корзину, CRM, доставку, документы и просроченные задачи.
5. Сделать панель "Арай-директор" с приоритетами дня.

## Статус Бренда

Все события проходят через главный статус: **Польза без вреда**.

Цель реестра - не автоматизировать хаос, а превращать каждый сигнал бизнеса в спокойное, понятное и подтверждаемое действие.
