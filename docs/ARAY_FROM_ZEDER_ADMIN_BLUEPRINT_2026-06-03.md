# ARAY From Zeder Admin Blueprint

Дата фиксации: 2026-06-03

Этот документ отвечает на вопрос: реально ли на базе админки Zeder / PiloRus сделать сайт и производственную систему ARAY.

Короткий ответ: да, реально. В текущей админке уже есть большая часть нужного фундамента. Нужно не писать все с нуля, а переупаковать готовые модули под маркетинговое агентство, партнерскую сеть и производство услуг.

## Главная идея переноса

Zeder / PiloRus сейчас работает как магазин:

товары -> корзина -> заказ -> клиент -> админка -> статусы -> задачи -> финансы -> медиа -> SEO.

ARAY должен работать как агентство:

услуги -> бриф -> маркетинговый заказ -> клиент -> партнер -> CRM -> статусы -> задачи производства -> счета -> отчеты -> сайт/PWA/реклама/SEO.

### 1. Партнеры

- имя/компания;
- страна;
- город;
- регион работы;
- ИП/ООО;
- статус проверки;
- договор;
- процент;
- рейтинг;
- лимит клиентов;
- активность;
- реквизиты;
- налоговый контур.

### 2. Партнерские сделки

Нужна сущность PartnerDeal:

- партнер;
- клиент;
- услуга/тариф;
- сумма клиента;
- доля партнера;
- доля ARAY;
- статус счета клиенту;
- статус оплаты клиентом;
- статус оплаты ARAY;
- период услуги;
- связанный производственный заказ.

### 3. Бриф бизнеса

Нужна сущность BusinessBrief:

- сфера бизнеса;
- город;
- сайт/соцсети;
- цели;
- проблемы;
- конкуренты;
- материалы;
- услуги;
- бюджет;
- сроки;
- брендовые пожелания;
- автоматизация;
- реклама;
- SEO;
- ИИ;
- файлы.

### 4. Производственный заказ

Нужна сущность ProductionOrder или расширение Order:

- тип заказа: товарный / маркетинговый;
- партнер;
- клиент;
- тариф;
- бриф;
- ТЗ;
- этапы производства;
- задачи;
- файлы;
- отчеты;
- запуск;
- сопровождение.

На первом этапе можно не ломать Order, а сделать отдельный маркетинговый контур рядом с ним. Так Zeder не пострадает.

### 5. Карта партнеров

Нужна публичная страница:

- страна;
- город;
- ближайшие партнеры;
- фильтр по региону;
- карточка партнера;
- кнопка заявки;
- если партнера нет, заявка идет в центральную команду.

## Первый MVP ARAY на базе админки

### Публичный сайт

- главная ARAY Production;
- блок "Маркетинговый отдел под ключ";
- услуги и тариф 150 000 рублей в месяц;
- партнерская программа;
- карта/список партнеров по городам;
- заявка клиента;
- заявка партнера.

### Админка

- заявки;
- партнеры;
- клиенты;
- маркетинговые заказы;
- брифы;
- счета/оплаты;
- задачи производства;
- услуги/тарифы;
- отчеты.

### Первый поток

1. Партнер регистрируется.
2. Админ проверяет партнера.
3. Партнер создает клиента.
4. Партнер создает заказ "Маркетинговый отдел под ключ".
5. Система фиксирует сумму 150 000 рублей.
6. Система фиксирует долю ARAY 75 000 рублей.
7. Клиент заполняет бриф.
8. Партнер отмечает оплату клиента.
9. Партнер оплачивает ARAY.
10. Создается производственный заказ.
11. Система создает задачи.
12. Команда ARAY / Yuva выполняет работу.

## Что важно не сломать

- не ломать текущий Zeder;
- не смешивать товарные заказы и маркетинговые заказы без явного типа;
- не запускать автоматические юридические документы до подтверждения модели;
- не пускать партнера к чужим клиентам;
- не делать оплату "на словах" без статуса и журнала;
- не обещать клиенту больше, чем реально входит в месяц.

## Самый короткий путь разработки

1. Создать ARAY-публичную страницу с услугой и партнерской программой.
2. Добавить в админку раздел "Партнеры".
3. Добавить в админку раздел "Маркетинговые заказы".
4. Добавить бизнес-бриф.
5. Связать маркетинговый заказ с задачами.
6. Связать партнерский заказ с оплатой ARAY.
7. Потом подключать автоматические счета, документы, карту, отчеты и Site Factory.

## Итог

Это реально, потому что Zeder / PiloRus уже содержит магазинный, CRM, сервисный, задачный, финансовый, медийный, SEO и ARAY-фундамент.

ARAY нужно строить как отдельный слой на этом фундаменте:

не копия магазина, а производственная CRM маркетингового агентства с партнерами, брифами, счетами, задачами и запуском сайтов/PWA.
