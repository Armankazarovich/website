# ARAY Production — workflow проектирования каждого раздела

Дата фиксации: 2026-04-30

## Главная схема работы

Каждый раздел ARAY Production проектируется вместе:

- Арман объясняет бизнес-видение, функции, синхронизации, страхи и желания пользователей.
- Codex проверяет это как архитектор, продуктолог, UX/UI-дизайнер и инженер.

Так мы объединяем реальный бизнес-опыт Армана и техническую дисциплину Codex.

## Что Арман рассказывает по разделу

Перед работой над разделом Арман может описать:

- для кого раздел;
- зачем он бизнесу;
- какие действия должны быть главными;
- какие кнопки нужны;
- какие внешние сервисы должны подключаться;
- какие данные должны храниться;
- какие ошибки опасны;
- какие роли должны видеть раздел;
- что менеджер делает каждый день;
- что владелец должен видеть быстро;
- что клиент должен почувствовать;
- чем должен помочь ARAY;
- какие функции нужны сейчас;
- какие функции можно оставить на будущее.

## Что Codex обязан проверить

Codex после этого проверяет:

- не пропущены ли важные сценарии;
- не перегружен ли раздел;
- какие функции должны быть в MVP;
- какие функции лучше отложить;
- какие интеграции безопасны;
- какие интеграции требуют юридической/технической проверки;
- какие роли и права нужны;
- какие данные нужны в базе;
- какие API нужны;
- как это работает на mobile/tablet/desktop/PWA;
- как раздел вписывается в дизайн-систему;
- как ARAY будет открывать, объяснять или выполнять действия;
- какие тесты и проверки нужны;
- как раздел потом масштабируется на другие ниши.

## Результат обсуждения

После обсуждения должен появиться маленький документ или чек-лист:

- смысл раздела;
- пользователи;
- основные действия;
- интеграции;
- роли;
- данные;
- UX;
- мобильная версия;
- риски;
- план реализации;
- что делаем сейчас;
- что оставляем на потом.

## Закон “гений-комбо”

Арман может знать бизнес-сценарии, которые не видны разработчику.

Codex может увидеть технические, юридические, UX и архитектурные риски, которые не видны бизнесу.

Сильное решение рождается тогда, когда оба слоя соединены.

## Практический порядок по PiloRus/admin

После стабилизации фундамента админки идем по разделам:

1. Рабочий стол / dashboard.
2. Заказы и новая касса.
3. Каталог / товары / категории.
4. Медиабиблиотека.
5. Клиенты и CRM.
6. Склад / остатки.
7. Доставка.
8. Финансы.
9. Команда / роли.
10. Настройки сайта.
11. PWA / уведомления / интеграции.
12. ARAY Assistant.

Каждый раздел проходит по workflow выше.
