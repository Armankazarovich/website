# ARAY Psychological UX Check Standard

Date: 2026-05-21

This is the comfort check for ARAY / PiloRus functions. It is not a medical or scientific psychological test. It is a practical product rule: every important function must feel understandable, calm, useful, and trustworthy for a real person.

## Core Question

Can a tired user understand what to do in the first 3 seconds?

If not, the interface needs simplification before more features are added.

## Screen Order Law

Every working screen should follow this order:

1. Current work area: what the user can do now.
2. Primary action: the next useful step.
3. Status and confidence: counts, state, warnings, saved/active markers.
4. Secondary tools: filters, preview, settings, links.
5. Explanation and benefits: lower on the page or inside a compact help area.

Do not put advantages, theory, or long explanations above the working objects unless the page is empty or onboarding is the main task.

## One-Touch Rule

On mobile, the most common action must be reachable with one clear tap:

- add to cart;
- reopen cart;
- save;
- publish;
- call or message;
- open related item;
- return to work area.

If the user has to search after an action, the flow is not ready.

## Stress Test

Before marking a feature as ready, check:

- what happens after success;
- what happens after failure;
- what happens on mobile with one hand;
- whether a popup hides the bottom menu correctly;
- whether the user can get back without confusion;
- whether important text fits in two lines;
- whether active/selected state is visible without being loud;
- whether disabled or planned functions look honestly disabled.

## Visual Comfort

ARAY visual comfort means:

- one style for related buttons and icons;
- no random colors for the same meaning;
- primary color only for real primary action;
- badges and counters should support attention, not shout;
- cards should be scan-friendly;
- repeated modules should use the same interaction pattern.

## Evidence

When UX is changed, add evidence:

- screenshot or video when layout changes;
- mobile and desktop note;
- command checks;
- short reason: what became easier for the user.

## Current Application

Stories admin page, 2026-05-21:

- working story cards moved above explanatory benefit blocks;
- compact working header added before the card grid;
- tips moved lower as reference content;
- the goal is to reduce reading friction and make the first visible task obvious.
