# ARAY Fast Launch Plan — ранний старт и первые примеры

Дата фиксации: 2026-04-30

## Цель

Быстро выйти из бесконечной разработки в демонстрацию живой системы.

Нужно иметь несколько качественных примеров, чтобы Арман мог приводить старых клиентов и показывать:

- сайт;
- админку;
- CRM;
- ARAY Assistant;
- PWA;
- стиль;
- быстрый бриф;
- путь заказа;
- партнёрскую/подписочную модель.

## Принцип

Не запускать весь мир сразу. Запустить 2-3 эталонных примера, которые доказывают платформу.

Скорость не должна означать сырость. Скорость достигается уменьшением объёма, а не снижением качества.

Каждый публичный пример должен быть доведён до уровня “можно показывать с гордостью”: шрифт, цвет, иконки, адаптивность, функции, формы, скорость, PWA, CRM и ARAY должны разговаривать одним языком.

Если пример не соответствует нашему уровню, он остаётся внутренним черновиком и не идёт клиенту.

## Первый эталон

PiloRus — главный боевой эталон.

Что должно быть стабильно:

- публичный сайт;
- админка;
- каталог;
- заказы;
- медиа;
- роли;
- PWA;
- ARAY-widget;
- скорость;
- мобильная версия;
- базовая аналитика.

PiloRus доказывает, что система работает на реальном бизнесе.

## Следующие демо-ниши

Выбирать ниши, где быстро видна польза:

1. Стройматериалы / строительный магазин.
2. Услуги мастера / ремонт / монтаж.
3. Кафе / доставка еды / локальная кухня.
4. Салон / запись на услугу.
5. Фрилансер-дизайнер / портфолио + заявки.

Не делать все сразу. Начать с 2-3.

## Быстрый сценарий для клиента

1. Арман показывает PiloRus.
2. ARAY задаёт клиенту короткий бриф.
3. За 30-60 минут собирается первый черновой сайт/структура.
4. Клиент видит:
   - главную;
   - каталог/услуги;
   - заявку/заказ;
   - CRM;
   - ARAY-помощника;
   - мобильный вид.
5. Клиент понимает: это не просто сайт, а рабочая система.

## Что продавать сначала

Не “AI мечту”, а понятный результат:

- сайт + админка;
- заявки/заказы в CRM;
- мобильная/PWA версия;
- ARAY помощник на сайте;
- базовая аналитика;
- сопровождение;
- подписка.

ARAY Production как большая экосистема показывается как путь развития, но первый чек должен быть понятным бизнесу.

## Продуктовая упаковка

Стартовые пакеты:

- Trial / диагностика: 14 дней, аудит и черновой прототип.
- Starter: сайт + заявки + базовый ARAY.
- Business: сайт + CRM + каталог/услуги + аналитика + PWA.
- Production: расширенный ARAY, автоматизация, контент, реклама, партнёрское сопровождение.

Цены и юридические условия нужно определить отдельно.

## Что делать завтра/ближайшим утром

1. Закончить PiloRus: критичные баги, админка, каталог, медиа, мобильная версия.
2. Проверить правки менеджеров по файлу презентации.
3. Составить список 3 старых клиентов/ниш для первых демо.
4. Подготовить мини-бриф клиента.
5. Сделать первый “демо-конструкторный” сценарий руками на базе текущего кода.
6. Зафиксировать, какие операции должны стать автоматическими в ARAY Constructor.

## Что нельзя

- Не обещать клиентам, что вся экосистема уже готова.
- Не брать слишком много клиентов одновременно.
- Не запускать клиента, пока формы, контакты, мобильная версия и заявки не проверены.
- Не выпускать пример, если визуальный стиль, шрифты, иконки, анимации или функции выглядят случайно.
- Не продавать рейтинг в бирже.
- Не обещать пассивный доход без условий.

## Мера успеха

Первый успех — не тысячи пользователей. Первый успех:

- 1-3 довольных клиента;
- понятная подписка;
- рабочая CRM;
- повторяемый процесс создания сайта;
- готовая презентация;
- доверие к ARAY как к живой технологии.
