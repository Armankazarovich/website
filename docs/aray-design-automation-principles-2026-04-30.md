# ARAY Design Automation Principles

Дата фиксации: 2026-04-30

## Главный закон

Дизайн ARAY нельзя развивать вручную по каждому экрану.

Все ключевые части должны быть централизованы и переиспользуемы:

- темы;
- палитры;
- шрифты;
- иконки;
- фоны;
- glass/liquid эффекты;
- hover/active/focus состояния;
- popups;
- side panels;
- headers;
- mobile docks;
- cards;
- tables;
- forms;
- charts;
- motion presets.

## Почему это важно

Платформа будет расти: PiloRus, новые клиенты, конструктор сайтов, биржа, CRM, ERP, мессенджер, ARAY, ARC.

Если каждый раздел будет иметь свой случайный стиль, система станет дорогой и хрупкой. Нужно один раз сделать эталонный набор, а дальше все разделы строить из него.

## Что должно меняться в один клик

- цветовая атмосфера;
- тёмная/светлая тема;
- пакет иконок;
- фон/набор фонов;
- степень glass-размытия;
- плотность интерфейса;
- стиль карточек;
- стиль popups/side panels;
- motion intensity;
- режим “performance first” для слабых устройств.

## Design Kit

Нужен единый ARAY Admin Design Kit:

- `AdminShell`
- `AdminHeader`
- `AdminRail`
- `AdminSidePanel`
- `AdminPopup`
- `AdminCard`
- `AdminMetricCard`
- `AdminActionCard`
- `AdminTable`
- `AdminForm`
- `AdminTabs`
- `AdminSearch`
- `AdminEmptyState`
- `AdminMobileDock`
- `ArayDock`
- `ArayPanel`

Каждый новый раздел должен брать эти компоненты, а не изобретать UI заново.

## Tokens first

Сначала токены, потом компоненты:

- цветовые токены;
- spacing;
- radius;
- border;
- shadow;
- blur;
- typography;
- icon size;
- motion duration/easing;
- z-index layers.

Если нужно изменить стиль всей платформы, мы меняем токены/пресеты, а не 200 файлов.

## Пакеты иконок

Иконки должны быть заменяемым слоем.

На старте можно использовать lucide как базу, но архитектура должна позволять:

- поменять набор;
- добавить фирменные ARAY-иконки;
- использовать разные веса/стили;
- сохранять одинаковые размеры и touch targets;
- не ломать навигацию при замене.

## Фоны и атмосферы

Фоны должны быть не “картинкой в CSS”, а набором пресетов:

- clean;
- photo;
- premium;
- performance;
- presentation;
- 9 атмосфер ARAY.

Каждый пресет знает:

- какие фото брать;
- насколько размывать;
- насколько затемнять/осветлять;
- какой glass использовать;
- как вести себя на мобиле;
- когда выключать эффекты для скорости.

## Что нельзя

- Не дублировать стили в каждом разделе.
- Не создавать отдельные “почти такие же” карточки.
- Не делать эффекты, которые нельзя централизованно отключить.
- Не привязывать дизайн к одной нише, если компонент должен быть платформенным.
- Не забывать mobile/PWA при создании desktop-компонента.

## Ближайшая реализация

1. Довести dashboard/admin shell до эталона.
2. Выделить повторяемые стили в токены и компоненты.
3. Применить kit к каталогу, заказам, клиентам, медиа.
4. Сделать appearance-настройки не декором, а управлением tokens/presets.
5. После стабилизации перенести подход на public site и будущий constructor.
