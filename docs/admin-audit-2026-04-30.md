# Admin Audit — 2026-04-30

Цель: держать админку ПилоРус в рабочем состоянии без потери контекста между сессиями.

## Проверено

- Локальный сервер поднят на `http://127.0.0.1:3000`.
- Авторизованный проход по ключевым разделам админки открыл страницы с `200`.
- Серверные логи после прохода без `Unhandled`, `TypeError`, `ReferenceError`, Prisma runtime ошибок.
- `npx tsc --noEmit` проходит чисто.
- Прод после последнего деплоя отвечает:
  - `/` — 200
  - `/catalog` — 200
  - `/login` — 200
  - `/api/health` — 200
  - `/admin/products` без авторизации корректно ведет на `/login`

## Важные выводы

- Критичного падения разделов на текущем проходе не найдено.
- Старые проблемы с переходами и Prisma-in-browser в каталоге закрыты, но каталог остается приоритетом для визуальной и функциональной полировки.
- Локальный dev-сервер иногда пишет Watchpack warnings по системным файлам диска `D:`. Это не прод-ошибка, но шум разработки стоит убрать отдельной мелкой правкой.
- Встроенная browser-панель в момент повторной проверки стала недоступна, поэтому повторные визуальные скриншоты нужно сделать, когда панель снова активна.

## Очередь работ

1. Каталог / товары:
   - проверить мобильный вид карточек и таблицы;
   - проверить фильтры, поиск, bulk-действия, редактирование;
   - убрать визуальный шум и выровнять плотность интерфейса.
2. Новый заказ:
   - превратить в удобную кассу нового поколения;
   - проверить сценарий создания заказа по телефону;
   - сделать мобильный и планшетный сценарий.
3. Заказы:
   - проверить статусы, корзину, архив, CSV, действия по строкам;
   - привести таблицу и карточки к единому стилю.
4. Навигация / хедер / мобильное меню:
   - повторить визуальный проход;
   - проверить все кнопки и доступность на телефоне.
5. Общий дизайн:
   - единая сетка, отступы, плотность, состояния hover/active;
   - убрать дубли и устаревшие элементы;
   - отдельно проверить светлую тему.

## Закон работы

- Маленькие изменения.
- Проверка перед деплоем.
- Коммит только проверенного.
- Прод не трогаем без smoke-check.

## Память стабилизации

- При каждом проходе админки проверять медиабиблиотеку: фото, видео, пустые превью, битые ссылки, загрузку, ALT, удаление и выбор из пикера.
- Отдельно проверять мобильные нажатия по карточкам дашборда и быстрым ссылкам: тап должен давать понятный переход, а не ощущение, что сервер не отвечает.
- Для каталога правило безопасного восстановления: если у товара нет фото, сначала искать точное совпадение `/images/products/{slug}.{webp|jpg|jpeg|png|gif}` и не перезаписывать фото, уже выбранные менеджером.
- Рабочий ритм стабилизации: один раздел админки — один проверенный пуш. Сначала чинить логику и роли, потом UI/UX.
- Медиабиблиотека: для команды единый вход `/admin/media` (товары, сайт, контент), `/cabinet/media` только для личных файлов покупателя.

## ARAY Liquid Glass — эталон админки

- Сеанс 2026-04-30: дашборд стал первым эталонным разделом для нового визуального языка админки.
- Направление: оригинальный ARAY/PiloRus liquid glass, без копирования Apple или чужих интерфейсов. Берем только общий принцип: глубина, стекло, свет, аккуратное движение, но форма, сетка, цвета, состояния и компоненты остаются нашими.
- Базовые классы для новых разделов: `admin-dashboard-standard`, `admin-liquid-surface`, `admin-liquid-interactive`, `admin-liquid-hero`, `admin-chrome-liquid`, `admin-rail-liquid`, `admin-popup-liquid`.
- Фоны админки: `clean` и `photo`. Видео в рабочей админке не использовать: вместо него фирменные фото с медленным parallax/zoom и плавной сменой, чтобы было красиво и легче для iPhone.
- Все новые карточки, таблицы, попапы, drawer-панели и hover-состояния должны наследовать токены темы (`--card`, `--border`, `--primary`) и работать в темной/светлой теме и будущих палитрах.
- Правило адаптивности: сначала mobile/tablet/desktop, затем большие экраны. Контент не должен вылезать за монитор; широкие таблицы получают управляемый горизонтальный скролл, а не ломают всю страницу.
- Правило качества: один раздел — один проверенный пуш. До пуша минимум `npx tsc --noEmit`, `npm run build:ci`, local smoke и после деплоя prod smoke.
- Local health 2026-04-30 может показывать `degraded`, если в локальном окружении нет `TELEGRAM_BOT_TOKEN` или `GOOGLE_AI`. База и маршруты при этом могут быть исправны; не путать это с падением сайта.
- Дизайн-правило фонов: фото не должно создавать грязь под текстом. Хедер, боковое меню и попапы — чистые рабочие поверхности; атмосферное фото живет ниже как приглушенный слой. Светлая тема идет в сторону чистой зимы, темная — лес/горы/водопады.
- UX-правило эффектов: градиенты, тени и hover используются только для иерархии, активного состояния и важных действий. Убрать дешевые полосы/блики и недоделанные анимации с рабочих карточек.
- Фирменный hover: один общий эффект `liquid border orbit` — неоновый свет выбранного пользователем цвета мягко бежит по кромке стеклянного элемента. Не добавлять конкурирующие shimmer/shine эффекты рядом.
- Эталон стиля: один тип фона, один тип стеклянной карточки, одна hover-анимация и одна логика боковой навигации. После согласования дашборда переносить этот стиль на остальные разделы без локальных вариаций.
- Типографика: подобрать 2-3 универсальных режима шрифтов максимум. Текст без теней, с хорошим контрастом на стекле и фото; заголовки выразительные, рабочий текст нейтральный и максимально читаемый.
- Мобильная проверка: если на desktop переходы стабильны, а на iPhone нажатия ведут себя странно, первым делом проверять кэш/PWA/service worker и старый JS-бандл. После деплоя обязательно просить hard refresh/очистку данных сайта перед выводом, что сломан код.
- Быстрое оформление: в боковом мини-переключателе оставить только простые действия — палитра, тема, чистый/атмосферный фон. Загрузку своих фото/видео скрыть до отдельного полноценного раздела оформления, чтобы не перегружать админку.

## Сеанс 2026-04-30 — стабилизация перед пушем

- Разделяем дизайн-пакеты: сейчас правим только админку. Публичный сайт идет отдельным проходом, чтобы не смешивать витрину и рабочую систему.
- Базовая защита от role-bugs: `SUPER_ADMIN` должен проходить там же, где проходит `ADMIN`, если раздел уже показан владельцу в интерфейсе. Полная матрица ролей остается отдельной задачей раздела пользователей/ролей.
- Причина возможного iPhone `Application error`: страница могла быть видимой в меню, а API отвечал `Unauthorized`; клиентский экран затем получал неправильные данные. Для финансов добавлена мягкая обработка ошибок, а очевидные owner-only API расширены на `SUPER_ADMIN`.
- Старые глобальные hover-анимации иконок в админке отключены. Новый стандарт: одна спокойная анимация `admin-liquid-interactive` с движением света по границе, без конкурирующих shimmer/rotate эффектов.
- Нижний мобильный док и мобильный popup уведомлений переведены на общий админский слой `admin-mobile-dock` / `admin-popup-liquid`.
- Заголовки секций получают единый стиль `admin-section-kicker`: читаемый, компактный, стеклянный, без грязного фона под текстом.
- Лишний баннер `Лаборатория ARAY` из мобильного account drawer убран: рабочее меню не должно отвлекать менеджеров от основных разделов.
- iPhone/PWA chrome: системная зона телефона должна подстраиваться под текущую светлую/темную тему через `theme-color`, `apple-mobile-web-app-status-bar-style` и клиентскую синхронизацию темы. Это отдельный слой от дизайна контента.
- После текущего пуша напомнить Арману про новое ТЗ ПилоРус для публичного сайта: файл нужно разобрать отдельным спокойным проходом после стабилизации админки.
- Боковая навигация админки: не использовать тяжелую стену или старый список. Эталон — легкий плавающий rail-док слева, активный раздел подсвечивается мягко, группы раскрываются в чистую стеклянную панель. На мобилке навигация живет в нижнем доке и account drawer, без лишних баннеров и дублирующего шума.
- Следующий большой дизайн-слой: `ARAY Command Search` в хедере на desktop и полноэкранный/попап поиск на mobile. Поиск должен стать центром управления по товарам, заказам, клиентам, задачам и позже по всем проектам конструктора.
- Будущая цветовая инфраструктура: не просто 9 цветов, а 9 атмосфер ARAY для разных типов людей и режимов бизнеса. Один интерфейс и одна логика компонентов, но разные эмоциональные палитры, фоновые наборы и акценты.
- Медиа-фоны: генерировать уникальный универсальный природный комплект для конструктора, не привязанный к пиломатериалам. Темная тема — лес, горы, водопады, ночь/рассвет; светлая — чистая зима, воздух, мягкий свет. Форматы WebP/AVIF, несколько размеров, статичные легкие файлы плюс плавный parallax/zoom вместо видео.
