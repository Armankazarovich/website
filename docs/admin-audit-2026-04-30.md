# Admin Audit — 2026-04-30

Цель: держать админку ПилоРус в рабочем состоянии без потери контекста между сессиями.

## Проверено

- Локальный сервер поднят на `http://127.0.0.1:3000`.
- Авторизованный проход по ключевым разделам админки открыл страницы с `200`.
- Серверные логи после прохода без `Unhandled`, `TypeError`, `ReferenceError`, Prisma runtime ошибок.
- `npx tsc --noEmit` проходит чисто.
- Прод после последнего деплоя отвечает:
  - `/` — 200
  - `/catalog` — 200
  - `/login` — 200
  - `/api/health` — 200
  - `/admin/products` без авторизации корректно ведет на `/login`

## Важные выводы

- Критичного падения разделов на текущем проходе не найдено.
- Старые проблемы с переходами и Prisma-in-browser в каталоге закрыты, но каталог остается приоритетом для визуальной и функциональной полировки.
- Локальный dev-сервер иногда пишет Watchpack warnings по системным файлам диска `D:`. Это не прод-ошибка, но шум разработки стоит убрать отдельной мелкой правкой.
- Встроенная browser-панель в момент повторной проверки стала недоступна, поэтому повторные визуальные скриншоты нужно сделать, когда панель снова активна.

## Очередь работ

1. Каталог / товары:
   - проверить мобильный вид карточек и таблицы;
   - проверить фильтры, поиск, bulk-действия, редактирование;
   - убрать визуальный шум и выровнять плотность интерфейса.
2. Новый заказ:
   - превратить в удобную кассу нового поколения;
   - проверить сценарий создания заказа по телефону;
   - сделать мобильный и планшетный сценарий.
3. Заказы:
   - проверить статусы, корзину, архив, CSV, действия по строкам;
   - привести таблицу и карточки к единому стилю.
4. Навигация / хедер / мобильное меню:
   - повторить визуальный проход;
   - проверить все кнопки и доступность на телефоне.
5. Общий дизайн:
   - единая сетка, отступы, плотность, состояния hover/active;
   - убрать дубли и устаревшие элементы;
   - отдельно проверить светлую тему.

## Закон работы

- Маленькие изменения.
- Проверка перед деплоем.
- Коммит только проверенного.
- Прод не трогаем без smoke-check.

## Память стабилизации

- При каждом проходе админки проверять медиабиблиотеку: фото, видео, пустые превью, битые ссылки, загрузку, ALT, удаление и выбор из пикера.
- Отдельно проверять мобильные нажатия по карточкам дашборда и быстрым ссылкам: тап должен давать понятный переход, а не ощущение, что сервер не отвечает.
- Для каталога правило безопасного восстановления: если у товара нет фото, сначала искать точное совпадение `/images/products/{slug}.{webp|jpg|jpeg|png|gif}` и не перезаписывать фото, уже выбранные менеджером.
- Рабочий ритм стабилизации: один раздел админки — один проверенный пуш. Сначала чинить логику и роли, потом UI/UX.
- Медиабиблиотека: для команды единый вход `/admin/media` (товары, сайт, контент), `/cabinet/media` только для личных файлов покупателя.
