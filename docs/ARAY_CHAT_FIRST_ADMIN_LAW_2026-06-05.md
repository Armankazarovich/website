# ARAY Chat-First Admin Law

Date: 2026-06-05

## Law

ARAY screens must feel like a guided assistant, not an aircraft control panel.

The main work starts in ARAY chat. The admin screen is a side workspace that opens the right page, shows the current step, and gives only the actions needed now.

## Interface Rules

1. First viewport shows one main step, not a map of the whole system.
2. Primary action is visible immediately: domain, scan, draft, preview, publish, or confirm.
3. Keep 2-3 main buttons per work screen. Move secondary links into service maps or details.
4. Explain only what the user needs for the next action. Long strategy, future layers, and internal architecture stay collapsed.
5. Partner-facing screens use plain business language. Super-admin/service language stays hidden.
6. ARAY may move across CRM, brief, builder, preview, SEO, PWA, analytics, finance, and launch pages, but the user experiences it as one guided chat flow.
7. Dangerous actions require confirmation: domain, payment, deletion, production deploy, irreversible data changes.

## Launch Screen Standard

The first launch screen must show:

- Step 1: choose one calm start method.
- Start methods: scan existing site, QUIZ with ARAY, CRM request, or template/new business.
- Primary action for scan: enter domain and scan.
- Secondary action for scan: create draft.
- Side note: ARAY chat guides the work and opens the right admin area.
- Below: working path, live CRM queue, and collapsed service map.

## Benchmark Law

- Current only battle-tested benchmark is PiloRus.
- WordPress Multisite meaning: one shared ARAY core, many separate sites. A new site starts as a draft tenant cloned from PiloRus, then Brief changes sphere, content, products/services, contacts, style and domain.
- A new ARAY site is not a landing page. It must inherit the whole working contour: public pages, catalog or services, request flow, CRM, admin, PWA, notifications, analytics, roles, SEO, and launch checks.
- Future benchmarks may be created with ARAY, but only after they pass the same contour standard.
- Changing a business means changing sphere, content, style, domain, products or services, prices, contacts, and integrations. The core functions must stay available unless deliberately disabled.
- The launch action "От PiloRus" must call the real multisite clone layer, not only create an empty Tenant/settings profile.

## What Not To Do

- Do not put every module, future idea, internal check, and service note on the first screen.
- Do not make the partner read architecture before starting.
- Do not make a new page that looks like a cockpit when one clear step is enough.
- Do not call a single visual page an etalon if it does not include the working contour.
