# ARAY Agent Mesh — 2026-05-01

ARAY Production должен развиваться как сеть управляемых AI-агентов, а не как один чат или набор ручных инструментов.

Цель: создать внутреннее "агентство автоматизации" внутри платформы, где каждый важный раздел имеет своего агента, свои проверки, свои журналы и свои права. Главный управляющий слой держит стандарты ARAY: качество, безопасность, дизайн, скорость, SEO, роли, уведомления, PWA и стабильность.

## Главный принцип

Агент — это не свободный бот без контроля. Агент — это роль в системе:

- зона ответственности;
- список разрешенных действий;
- список запретных действий;
- входные события;
- расписание проверок;
- quality gate;
- журнал решений;
- отчет человеку;
- правила эскалации.

Закон: агент может действовать сам только там, где действие безопасное, обратимое и не нарушает деньги, закон, данные, роли, доверие пользователя или продакшен.

## Директорская модель

Верхний слой:

- ARAY Director Agent — общий контроль проекта, стандартов, приоритетов и отчетов.
- Quality Gate Agent — проверяет сборку, типы, секреты, визуальные регрессии, PWA, SEO, performance.
- Product Memory Agent — обновляет документацию, changelog, handoff, карту решений и следующий шаг.
- Risk/Security Agent — следит за секретами, доступами, опасными действиями, массовыми операциями и audit log.

Разделы продукта:

- Design System Agent — цвета, иконки, отступы, hover/glow, стекло, попапы, mobile/tablet/desktop.
- Dashboard Agent — структура дашборда, карточки, пульс заказов, быстрый доступ, готовность, пустые состояния.
- SEO/Growth Agent — sitemap, robots, canonical, GET-параметры, дубли, schema, Open Graph, фиды, рост страниц.
- Performance Agent — Core Web Vitals, тяжелые страницы, картинки, кеш, API, SQL, индексы, очереди.
- Notifications Agent — push, email, кабинет/in-app, Telegram, шаблоны, quiet hours, delivery log.
- CRM/Sales Agent — лиды, туннели, заказы, клиенты, задачи, автоматизации, напоминания.
- Media/Asset Agent — фото, фоны, оптимизация, битые изображения, favicon, PWA icons, source map ассетов.
- PWA/Role Apps Agent — manifest по tenant/role, icons, theme-color, safe-area, offline, driver/touch режимы.
- Integration Agent — касса, платежи, Telegram, email, API, webhooks, retry, журналы ошибок.
- Support/Knowledge Agent — справка, ответы пользователям, обучение, объяснение функций, документация.

## 24/7 режим

Постоянная работа строится не магией, а системно:

- расписания/cron для регулярных проверок;
- очереди для тяжелых задач;
- webhooks для событий;
- health-check после деплоя;
- мониторинг ошибок, скорости, диска, памяти и API;
- отчеты в кабинет и важные каналы;
- автоматические задачи на исправление безопасных проблем;
- ручное подтверждение для рискованных действий.

Закон: агент не должен молча "что-то делать" в проде. Каждое действие должно оставлять след: что увидел, почему решил, что сделал, что получилось, где откатить.

## Уровни автономности

Level 0 — советник:
агент только анализирует и пишет рекомендацию.

Level 1 — черновик:
агент готовит правку, задачу, текст, шаблон или отчет, но не применяет сам.

Level 2 — безопасное автоисправление:
агент сам исправляет формат, документацию, битые ссылки внутри безопасной зоны, мелкие SEO-поля, неопасные настройки.

Level 3 — контролируемое действие:
агент делает PR/commit/задачу, но деплой, массовая рассылка, деньги, роли и удаления требуют подтверждения.

Level 4 — рабочая автоматика:
для проверенных сценариев: отправить уведомление, повторить доставку, обновить sitemap, пересчитать кеш, создать напоминание, собрать отчет.

Level 5 — запрещено без человека:
платежи, возвраты, удаление данных, массовые рассылки, изменение ролей, юридические действия, раскрытие секретов, опасные AI-действия, изменения прод-БД.

## Обязательные защиты

- Все агенты работают через роли и permission matrix.
- Все действия пишутся в audit log.
- Все внешние отправки имеют delivery log.
- Все массовые операции имеют лимиты, preview и подтверждение.
- Все опасные действия имеют human approval.
- Все prod-изменения проходят quality gate.
- Все ключи живут только в env/server.
- Tenant/client данные изолированы.
- Агент не должен притворяться, что функция готова, если она не подключена.

## Как внедрять

1. Закрепить архитектуру Agent Mesh в документах и приоритетах.
2. Сделать единый реестр событий и уведомлений.
3. Расширить ARAY Quality Gate проверками PWA, SEO, performance и изображений.
4. Добавить Agent Control Center в админку: состояние агентов, отчеты, последние действия, ошибки, задачи.
5. Начать с безопасных агентов: docs/memory, quality, SEO-аудит, performance-аудит, image-аудит, notification delivery.
6. После ПилоРус-эталона масштабировать на клиентские сайты и конструктор.

Закон: ARAY Agent Mesh должен помогать Codex и Арману двигаться быстрее, но не должен забирать контроль. Главный контроль остается у архитектуры, правил, журналов, качества и человека в рискованных местах.
