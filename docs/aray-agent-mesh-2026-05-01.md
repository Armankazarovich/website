# ARAY Agent Mesh — 2026-05-01

ARAY Production должен развиваться как сеть управляемых AI-агентов, а не как один чат или набор ручных инструментов.

Цель: создать внутреннее "агентство автоматизации" внутри платформы, где каждый важный раздел имеет своего агента, свои проверки, свои журналы и свои права. Главный управляющий слой держит стандарты ARAY: качество, безопасность, дизайн, скорость, SEO, роли, уведомления, PWA и стабильность.

## Главный принцип

Агент — это не свободный бот без контроля. Агент — это роль в системе:

- зона ответственности;
- список разрешенных действий;
- список запретных действий;
- входные события;
- расписание проверок;
- quality gate;
- журнал решений;
- отчет человеку;
- правила эскалации.

Закон: агент может действовать сам только там, где действие безопасное, обратимое и не нарушает деньги, закон, данные, роли, доверие пользователя или продакшен.

## Директорская модель

Верхний слой:

- ARAY Director Agent — общий контроль проекта, стандартов, приоритетов и отчетов.
- Quality Gate Agent — проверяет сборку, типы, секреты, визуальные регрессии, PWA, SEO, performance.
- Product Memory Agent — обновляет документацию, changelog, handoff, карту решений и следующий шаг.
- Risk/Security Agent — следит за секретами, доступами, опасными действиями, массовыми операциями и audit log.

Разделы продукта:

- Design System Agent — цвета, иконки, отступы, hover/glow, стекло, попапы, mobile/tablet/desktop.
- Dashboard Agent — структура дашборда, карточки, пульс заказов, быстрый доступ, готовность, пустые состояния.
- SEO/Growth Agent — sitemap, robots, canonical, GET-параметры, дубли, schema, Open Graph, фиды, рост страниц.
- Performance Agent — Core Web Vitals, тяжелые страницы, картинки, кеш, API, SQL, индексы, очереди.
- Notifications Agent — push, email, кабинет/in-app, Telegram, шаблоны, quiet hours, delivery log.
- CRM/Sales Agent — лиды, туннели, заказы, клиенты, задачи, автоматизации, напоминания.
- Media/Asset Agent — фото, фоны, оптимизация, битые изображения, favicon, PWA icons, source map ассетов.
- PWA/Role Apps Agent — manifest по tenant/role, icons, theme-color, safe-area, offline, driver/touch режимы.
- Integration Agent — касса, платежи, Telegram, email, API, webhooks, retry, журналы ошибок.
- Support/Knowledge Agent — справка, ответы пользователям, обучение, объяснение функций, документация.

## Иерархия как умная компания

ARAY Agent Mesh должен работать как большая профессиональная компания, где у каждого есть своя зона ответственности, свой отчет и свой уровень прав.

### Level 0: владелец и стратегия

- Арман — видение, вкус, бизнес-смысл, приоритеты, доверие к людям.
- Codex / ARAY Director — генеральный директор архитектуры: держит систему, качество, безопасность, темп, стандарты и честное объяснение.

### Level 1: заместители генерального директора

- Product Deputy Agent — следит, чтобы каждая функция имела смысл, сценарий, ценность, роли и путь развития.
- Engineering Deputy Agent — отвечает за архитектуру, код, сборку, API, БД, очереди, интеграции и техдолг.
- Quality Deputy Agent — отвечает за ARAY Quality Score, тесты, визуальные проверки, PWA, доступность, скорость и регрессии.
- Growth Deputy Agent — SEO, аналитика, реклама, индексация, контент, фиды, рост страниц и отчеты.
- Operations Deputy Agent — стабильность прода, health-check, деплой, бэкапы, мониторинг, инциденты и восстановление.
- Security Deputy Agent — секреты, роли, права, audit log, платежи, персональные данные, опасные действия и approvals.
- Customer Success Deputy Agent — поддержка, обучение, кабинет, уведомления, понятность интерфейса и обратная связь.

### Level 2: отделы

- Design System Department: атмосферы, токены, иконки, попапы, карточки, hover/glow, mobile/tablet/desktop.
- Dashboard Department: рабочий стол, пульс заказов, быстрый доступ, готовность, виджеты, пустые состояния.
- Orders/CRM Department: заказы, лиды, клиенты, туннели, задачи, напоминания, автоматизации.
- Catalog/Media Department: товары, категории, фото, видео, медиа-библиотека, оптимизация, битые ассеты.
- Finance/Payments Department: оплаты, счета, касса, документы, возвраты, сверка, роли доступа.
- Notifications Department: push, email, кабинет/in-app, Telegram, шаблоны, quiet hours, delivery log.
- SEO/Growth Department: sitemap, robots, canonical, schema, Open Graph, фиды, дубли, GET-параметры.
- PWA/Role Apps Department: админка, клиентский сайт, курьер, касса, водитель, официант, склад, touch/voice режимы.
- Integrations Department: Telegram, email, платежи, касса, CRM/ERP, webhooks, retry, внешние API.
- Knowledge/Support Department: справка, обучение, ответы, инструкции, база знаний, объяснение ошибок.

### Level 3: рабочие агенты

Рабочий агент делает конкретную повторяемую работу внутри отдела:

- проверяет одну зону;
- исправляет только безопасное и обратимое;
- создает задачу, если нужно решение человека;
- пишет короткий отчет своему отделу;
- повышает сигнал наверх, если есть риск.

Примеры: Image Audit Worker, Broken Link Worker, Sitemap Worker, Push Delivery Worker, Email Template Worker, Mobile Layout Worker, Slow API Worker, Secret Scan Worker, Order Status Worker.

### Level 4: датчики и мониторы

Датчики ничего не меняют сами. Они только измеряют и сигналят:

- скорость страниц;
- ошибки API;
- битые изображения;
- размер JS/CSS;
- 404/500/soft404;
- статус деплоя;
- состояние очередей;
- доставку уведомлений;
- просадку SEO-страниц;
- подозрительные действия и доступы.

Закон: чем ниже уровень агента, тем меньше у него прав. Чем выше риск, тем быстрее сигнал поднимается к директорскому слою.

## Отчетность и индикаторы

Каждый агент должен иметь понятный отчет:

- что проверено;
- что найдено;
- что исправлено автоматически;
- что требует решения;
- текущий ARAY Quality Score;
- риск: `green`, `yellow`, `red`, `blocked`;
- следующий шаг с максимальной пользой.

Agent Control Center должен показывать:

- здоровье по отделам;
- последние действия агентов;
- красные и желтые зоны;
- очередь задач;
- что ожидает подтверждения;
- что исправлено автоматически;
- что стало лучше за день/неделю;
- где качество падает повторно.

Закон: Арман и Codex должны видеть не поток технического шума, а ясную картину компании: какой отдел здоров, где риск, кто отвечает, что уже исправлено и что нужно решить.

## Закон ответственного отдела

В ARAY не должно быть темных углов: ни страницы, ни API, ни базы, ни интеграции, ни кнопки, ни уведомления, ни SEO-правила, ни файла, за который никто не отвечает.

Каждая зона продукта должна иметь:

- responsible department — отдел-владелец;
- owner agent — агент, который отвечает за качество зоны;
- reviewer agent — агент из соседнего отдела, который проверяет взглядом со стороны;
- quality score — текущая оценка по матрице ARAY;
- risk status — `green`, `yellow`, `red`, `blocked`;
- audit trail — что менялось, кем, когда и почему;
- next action — что делать дальше, если качество не идеально.

Примеры ответственности:

- страница админки: Product + Design System + Quality;
- API: Engineering + Security + Performance;
- база данных: Engineering + Security + Operations;
- публичная SEO-страница: Growth + Performance + Design System;
- уведомление: Notifications + Product + Security;
- платеж или касса: Finance/Payments + Security + Operations;
- медиа и фото: Catalog/Media + Performance + Design System;
- PWA/роль: PWA/Role Apps + Security + Product.

Закон: если у зоны нет владельца, она считается `blocked`, даже если визуально работает.

## Перекрестная проверка

Агенты должны проверять друг друга, чтобы качество не зависело от одного взгляда.

Минимальная схема:

- Owner Agent проверяет свою зону и исправляет безопасное.
- Reviewer Agent проверяет риски, которые владелец мог пропустить.
- Quality Deputy Agent сверяет результат с ARAY Quality Score.
- Security Deputy Agent подключается к ролям, данным, деньгам, рассылкам и внешним интеграциям.
- ARAY Director принимает решение: исправить сейчас, поставить задачу, обсудить с Арманом или заблокировать рискованное действие.

Закон: спор между агентами решается не шумом, а данными: риск, пользовательский эффект, безопасность, деньги, скорость, SEO, доверие и стоимость исправления.

## Карта контроля кода и функций

Для роста платформы нужна живая карта контроля:

- какой раздел за какой отдел отвечает;
- какие файлы и API входят в раздел;
- какие проверки уже автоматизированы;
- какие проверки пока ручные;
- где есть риск, долг или неизвестность;
- какие агенты смотрели зону последними;
- когда была последняя зеленая проверка;
- где нужен human approval.

Закон: новый раздел нельзя считать зрелым, пока он не внесен в карту контроля и не имеет владельца, проверяющего, quality score и правила уведомлений.

## Защита от перегруза

Агентная система не должна перегружать проект, сервер, команду и пользователя.

Правила:

- агенты запускаются по расписанию, событию или приоритету, а не все одновременно;
- тяжелые проверки идут через очереди и лимиты;
- массовые задачи имеют rate limit;
- низкоприоритетные проверки не мешают заказам, оплатам, сайту и админке;
- одинаковые сигналы группируются;
- отчеты сворачиваются в понятные сводки;
- автоисправления ограничены безопасными зонами;
- новые агенты добавляются только если они убирают реальную ручную работу или риск.

Закон: агентная сеть должна делать жизнь спокойнее, а не создавать новый шум.

## 24/7 режим

Постоянная работа строится не магией, а системно:

- расписания/cron для регулярных проверок;
- очереди для тяжелых задач;
- webhooks для событий;
- health-check после деплоя;
- мониторинг ошибок, скорости, диска, памяти и API;
- отчеты в кабинет и важные каналы;
- автоматические задачи на исправление безопасных проблем;
- ручное подтверждение для рискованных действий.

Закон: агент не должен молча "что-то делать" в проде. Каждое действие должно оставлять след: что увидел, почему решил, что сделал, что получилось, где откатить.

## Уровни автономности

Level 0 — советник:
агент только анализирует и пишет рекомендацию.

Level 1 — черновик:
агент готовит правку, задачу, текст, шаблон или отчет, но не применяет сам.

Level 2 — безопасное автоисправление:
агент сам исправляет формат, документацию, битые ссылки внутри безопасной зоны, мелкие SEO-поля, неопасные настройки.

Level 3 — контролируемое действие:
агент делает PR/commit/задачу, но деплой, массовая рассылка, деньги, роли и удаления требуют подтверждения.

Level 4 — рабочая автоматика:
для проверенных сценариев: отправить уведомление, повторить доставку, обновить sitemap, пересчитать кеш, создать напоминание, собрать отчет.

Level 5 — запрещено без человека:
платежи, возвраты, удаление данных, массовые рассылки, изменение ролей, юридические действия, раскрытие секретов, опасные AI-действия, изменения прод-БД.

## Обязательные защиты

- Все агенты работают через роли и permission matrix.
- Все действия пишутся в audit log.
- Все внешние отправки имеют delivery log.
- Все массовые операции имеют лимиты, preview и подтверждение.
- Все опасные действия имеют human approval.
- Все prod-изменения проходят quality gate.
- Все ключи живут только в env/server.
- Tenant/client данные изолированы.
- Агент не должен притворяться, что функция готова, если она не подключена.

## ARAY Quality Score для каждого агента

Каждый агент обязан оценивать качество своей зоны по единой матрице ARAY. Агент без оценки качества — это не агент ARAY, а просто автоматизация без ответственности.

Обязательные параметры оценки:

- смысл и бизнес-польза;
- рабочая логика от А до Я;
- UX и понятность для человека без технических знаний;
- дизайн по ARAY Design System: цвета, иконки, стекло, hover/glow, отступы, шрифты;
- mobile, tablet, desktop, PWA, touch, большие экраны;
- скорость, вес страницы, кеш, API, SQL, изображения;
- безопасность, роли, права, audit log;
- уведомления: push, email, кабинет/in-app, Telegram, quiet hours, delivery log;
- SEO и рост для публичных страниц;
- доступность: фокус, контраст, keyboard, touch targets;
- данные: пустые состояния, ошибки, загрузка, пагинация, дубли, целостность;
- прод-стабильность: health-check, rollback, мониторинг, отсутствие секретов.

Каждый агент должен возвращать понятный статус:

- `green` — зона здорова;
- `yellow` — есть улучшения, но прод не под угрозой;
- `red` — есть риск качества, доверия, данных, скорости, безопасности или денег;
- `blocked` — агент не может честно проверить без данных, доступа или подключенной функции.

Закон: агент не должен молча считать задачу завершенной. Он должен показать оценку, найденные риски, что исправил сам, что требует контроля и какой следующий шаг даст максимальный прирост качества.

Закон: все повторяющиеся проверки качества постепенно переносятся в автоматический quality gate, чтобы ARAY не зависел от памяти человека.

## Как внедрять

1. Закрепить архитектуру Agent Mesh в документах и приоритетах.
2. Сделать единый реестр событий и уведомлений.
3. Расширить ARAY Quality Gate проверками PWA, SEO, performance и изображений.
4. Добавить Agent Control Center в админку: состояние агентов, отчеты, последние действия, ошибки, задачи.
5. Начать с безопасных агентов: docs/memory, quality, SEO-аудит, performance-аудит, image-аудит, notification delivery.
6. После ПилоРус-эталона масштабировать на клиентские сайты и конструктор.

Закон: ARAY Agent Mesh должен помогать Codex и Арману двигаться быстрее, но не должен забирать контроль. Главный контроль остается у архитектуры, правил, журналов, качества и человека в рискованных местах.
