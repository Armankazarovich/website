# ARAY Session Handoff

Дата: 2026-06-04

## Что сделали

- Перенесли публичный `/aray` из свежей ARAY Production версии в рабочую папку.
- Добавили публичные входы:
  - `/aray/marketing/apply` — клиентская заявка на маркетинг/сайт/PWA/CRM;
  - `/aray/partners/apply` — заявка партнера;
  - `/aray/partners/yuva-studio` — первый партнерский профиль.
- Добавили формы `ArayMarketingApplicationForm` и `ArayPartnerApplicationForm`.
- Добавили `/api/aray/marketing-leads`: клиентская заявка создает CRM-лид с тегами ARAY, суммой 150 000 ₽, комментарием и системной активностью.
- Обновили `/api/partnership`: партнерская заявка теперь создает `PartnershipLead` и CRM-лид с ARAY-тегами и системной активностью.
- Добавили `lib/aray-crm-automation.ts` как единое место для тегов, суммы и текста активности ARAY-заявок.
- Перенесли публичные бренд-материалы `public/aray/brand-assets`, чтобы ссылки в бренд-комплекте и партнерских страницах не были пустыми.
- В `/admin/aray/orders` добавили живую очередь ARAY CRM: последние клиентские заявки, сумма, статус, телефон, комментарий, системная заметка и следующий шаг.
- Связали очередь с конкретной заявкой: кнопка `Собрать бриф` ведет в `/admin/aray/briefs?leadId=...`, а `Запуск сайта` ведет в `/admin/aray/builder?leadId=...`.
- В `/admin/aray/briefs` добавили черновик брифа из CRM-лида: клиент, партнер, город, сфера, интерес, задача, недостающие поля и следующие действия.
- В `/admin/aray/builder` добавили блок запуска по CRM-заявке, чтобы Builder открывался не пустым экраном, а с контекстом клиента.
- Добавили `/api/admin/aray/launch/prepare`: закрытое действие, которое по `leadId` фиксирует запуск, создает системную заметку в истории лида и первые задачи ARAY Launch.
- Добавили кнопку `Зафиксировать бриф` в брифе и Builder: она превращает черновик в рабочий пакет задач без новой миграции базы.
- В Builder добавили первый план сайта из блоков: эталон, готовность, стартовые секции, поля для доспроса и ожидаемые выходы.
- Добавили `/api/admin/aray/launch/block-plan`: закрытое сохранение выбранных блоков в историю CRM-лида и задачу `ARAY_BLOCK_PLAN`.
- Заменили статичный список блоков в Builder на интерактивную студию: блоки можно включать/убирать, видеть объяснение шага и сохранять план в CRM.
- Каждый блок первого плана теперь получает черновик Арая: заголовок, короткий текст и действие. При сохранении плана эти черновики уходят в историю CRM-лида.
- В интерактивной студии добавили живое превью первой страницы: выбранные блоки сразу складываются в набросок сайта с главным экраном, составом услуги, CRM-путем, формой, ценой и футером.
- Добавили ручное редактирование черновиков блоков прямо в Builder: заголовок, текст и действие меняют живое превью сразу.
- Сохранение плана теперь отправляет утвержденные версии блоков в `/api/admin/aray/launch/block-plan`, пишет их в историю лида и структурно кладет в metadata связи задачи.
- Добавили `/api/admin/aray/launch/site-shell`: закрытое действие, которое по `leadId` и выбранным блокам создает отдельный `Tenant`-черновик сайта, сохраняет `storeConstructor`/`arayLaunch` в settings, пишет активность в CRM и создает задачу `ARAY_SITE_SHELL`.
- В интерактивной студии Builder появилась кнопка `Создать черновик сайта`: она отправляет выбранные/отредактированные блоки, показывает tenant, ссылку на превью и ссылку в конструктор.
- `/admin/site/constructor?tenant=...` теперь подхватывает созданный ARAY-черновик из списка сайтов и открывает его в режиме запуска.

## Что это значит

Первый путь стал настоящим:

`/aray` -> `Заказать систему` -> форма -> CRM Lead -> `/admin/aray/orders` -> `/admin/aray/briefs?leadId=...` -> `Зафиксировать бриф` -> задачи запуска -> `/admin/aray/builder?leadId=...` -> выбор блоков -> сохранение плана в CRM -> `Создать черновик сайта` -> Tenant draft -> превью/конструктор.

OpenAI для этого не нужен. Текущий слой работает на базе проекта, CRM, Yandex/Claude-ready архитектуры и будущих подключаемых провайдеров.

## Закон

Не строить вокруг ARAY красивые отдельные страницы без живого пути. Каждая публичная кнопка должна вести к CRM, брифу, счету, производству или понятному следующему шагу.

## Вечерний фикс перед стартом нового сайта

Дата фиксации: 2026-06-04, вечер.

Главное решение:

- Не продолжаем путаться с внешним Зейдром внутри локальной ARAY-системы.
- PiloRus остается золотой базой и эталоном механики.
- Зейдр/Zaidr считается отдельным внешним сервером и не должен отображаться как переключаемый сайт в локальной админке PiloRus.
- Новый сайт завтра начинаем через ARAY Launch: домен -> скан -> бриф -> черновик -> превью -> проверка -> домен/публикация.

Что закреплено технически:

- Переключатель активного сайта в админке показывает только ARAY-managed сайты, сейчас это PiloRus.
- Кнопка "Добавить сайт" доступна владельцу/админу и ведет в `/admin/aray/orders#aray-site-import`.
- Блок скана сайта находится на `/admin/aray/orders#aray-site-import`.
- Старые тексты "Зейдр/Зедер" убраны из рабочих ARAY-экранов запуска, чтобы не сбивать направление.
- Middleware больше не мапит `zaidr.ru` как локальный tenant.
- В `.env.example` оставлена схема будущей доменной карты без привязки Зейдра к локальной админке.
- Товары, категории, настройки сайта, публичный каталог, карточка товара, шапка/футер, сторис, Google Sheets, SMTP, Metrika, Direct, watermark, media ALT и AI-create-product переведены на tenant-aware логику.
- В Prisma схема переведена на уникальность внутри сайта:
  - `Category`: `@@unique([tenantId, slug])`;
  - `Product`: `@@unique([tenantId, slug])`;
  - `SiteSettings`: `@@unique([tenantId, key])`.
- Добавлена и применена локально миграция `prisma/migrations/20260604000000_tenant_scoped_site_unique_keys`.
- После временного `prisma generate --no-engine` клиент восстановлен обычным `npx prisma generate`, чтобы runtime снова работал с PostgreSQL, а не ждал `prisma://`.
- Основной dev-сервер снова поднят на `http://localhost:3101`.

Проверки вечернего фикса:

- `npx tsc --noEmit --pretty false` — прошел.
- `npm run release:check` — прошел.
- `npm run release:smoke` — прошел, включая `/catalog`.
- `npm run nav:check` — прошел.
- `npm run module-nav:check` — прошел.
- Браузер: `/admin/aray/orders#aray-site-import` открыт, переключатель имеет "Добавить сайт", в меню нет "Зейдр/Зедер".
- Браузер: блок "Скан сайта" и кнопка скана на месте, превью-слой есть.

Завтра первый рабочий шаг:

1. Открыть `http://localhost:3101/admin/aray/orders#aray-site-import`.
2. Нажать/использовать путь "Добавить сайт" только как вход в ARAY Launch, не как переключение на чужую админку.
3. Ввести домен нового клиента для скана.
4. Дать ARAY собрать первичный профиль: ниша, товары/услуги, структура, бренд, блоки, риски.
5. Создать черновик сайта и проверить превью.
6. Только после проверки данных, фото, заявок, PWA, SEO, CRM и smoke-теста говорить о подключении домена.

Что не забыть перед боем:

- На сервере/проде обязательно выполнить `npx prisma migrate deploy`, потому что локальная миграция уже применена, а боевая база должна получить те же tenant-unique индексы.
- Настоящий WordPress-Multisite уровень еще требует динамического списка ARAY-created сайтов в переключателе после публикации, но опасная путаница с внешним Зейдром уже снята.
- Не подключать боевой домен до финального превью и smoke-проверки.
