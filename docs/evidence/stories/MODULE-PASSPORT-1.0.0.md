- Обложка из кадра вместо белой карточки со значком: короткое видео получает обложку при загрузке; у старой сторис без обложки — кнопка «Сделать обложку» (записывается только пустая обложка). Где кадра всё же нет — спокойный фон без значка, на странице сторис — кадр из самого ролика.

- Список сторис на узких экранах: на телефоне маленькое превью слева и кнопки отдельной строкой; одна карточка в ряд до 1280 точек, две — до 1800; длинные подписи кнопок переносятся, а не обрезаются.

## Медиа-контракт 1.0.0

1. Оригинал никогда не перезаписывается и не удаляется обработчиком.
2. Тяжёлый MP4 больше 24 МиБ, MOV и WebM обрабатываются в фоне; совместимый MP4 до 24 МиБ используется напрямую.
3. Лёгкая копия: MP4, H.264, `yuv420p`, AAC 96 кбит/с, до 30 кадров/с, не более 720×1280, CRF 23, ограничение потока 4 Мбит/с, `faststart`.
4. Одновременно работает только один процесс кодирования, чтобы не перегружать VPS.
5. Публикация происходит только после полного декодирования, проверки профиля, уменьшения размера и готовности постера.
6. Для существующей сторис меняется только `mediaUrl` — и `posterUrl`, если обложки не было. Заголовок, описание, связи, кнопка, просмотры, активность, закрепление и порядок не меняются.
7. Замена — условная публикация: если менеджер изменил `mediaUrl` после запуска задания, автоматическая публикация останавливается без перезаписи его работы.
8. После перезапуска приложения незавершённая очередь восстанавливается из квитанции. Уже проверенная копия повторно не кодируется.
9. Ошибка не запускает бесконечные автоматические повторы. Менеджер получает понятное сообщение и кнопку «Повторить».
10. Откат меняет только `mediaUrl` с лёгкой копии на зафиксированный оригинал и прекращается при конфликте с ручным изменением.
11. Исходник длиннее 180 секунд (плюс 1 секунда допуска) отвергается до сжатия с понятной причиной; длина, которую не удалось определить, не отвергается — итоговую копию всё равно проверяет профиль.
12. Обложка из кадра (кадр на 0,5 с, не больше 720×1280): для совместимого MP4 до 24 МиБ — при загрузке, файл видео не меняется ни на байт, сбой обложки не мешает загрузке; для существующей сторис — по кнопке «Сделать обложку» и только если обложки нет (условная запись в пустую `posterUrl`). Кадр пишется во временный файл и переименовывается — полуготовая обложка не видна.

## Файлы и сохранность

- новый тяжёлый исходник: `public/images/stories/originals/<stem>.<ext>`;
- временный результат: `<stem>-web.processing.mp4`;
- проверенный результат: `<stem>-web.mp4`;
- постер лёгкой копии и короткого видео: `<stem>-poster.jpg`;
- обложка по кнопке: `<имя видео>-poster-<время>.jpg` рядом с видео;
- квитанция и точный откат: `.story-media-jobs/<uuid>.json`;
- `.env`, `public/uploads`, `public/images` и `.story-media-jobs` не удаляются code-only deploy-процессом;
- Prisma-схема, миграции и `data-migrate` в 1.0.0 не меняются.

## Состояния и восстановление

`QUEUED -> PROCESSING -> PUBLISHING -> READY`

Сбой переводит задание в `FAILED`. Разрешён явный повтор по действию менеджера. Если процесс оборван перезапуском сервера, опрос статуса безопасно возвращает задание в очередь. Временные `.processing`-файлы не публикуются.

## Роли и защищённые действия

- посетитель: просмотр, пауза, звук, листание, кнопка сторис, сообщение продавцу;
- сотрудник: чтение списка сторис по действующим правилам;
- `MANAGER`, `ADMIN`, `SUPER_ADMIN`: создание, подготовка, повтор, откат, обложка из кадра, порядок;
- API записи требует подтверждения записи (`confirm: true`) и привязан к текущему `tenantId`; экран не показывает окно подтверждения только для обратимых действий;
- произвольные внешние URL и выход за `public/images/stories` для серверной обработки запрещены.

## Зависимости и переносимость

- runtime: Node.js 20, файловая система с постоянным хранилищем, Prisma и FFmpeg;
- бинарник поставляется через точную зависимость `ffmpeg-static@5.3.0` и берётся из папки пакетов, а не из серверной сборки;
- текущий профиль использует `libx264`; перед внешней поставкой или коммерческим распространением бинарника требуется отдельная проверка лицензии GPL и патентных условий H.264;
- модуль — клиентский выпуск PiloRus. Перенос в Zeder или ARAY выполняется только по цепочке `contract tests -> ArmanGlass -> shadow -> canary -> stable`, без копирования дерева проекта и без переноса данных PiloRus.

## Обязательный шлюз

- `npm run stories:media:check` — реальное кодирование, проверка профиля, сохранение оригинала, ошибка, повтор, публикация, обложка, откат и обложка из кадра для короткого видео;
- `npm run stories:check` — контракт, владельцы модуля и сторожа удобства;
- `npx tsc --noEmit --pretty false`, `npm run design:check`, `npm run text:check`;
- сборка без `db push` и без `data-migrate` (`next build` напрямую; обычный `npm run build` в этом проекте их запускает);
- `node scripts/validate-stories-preview-recovery.js` — закрытый виджет не трогает тяжёлое видео, ошибка превью не зацикливается;
- настоящий браузер: админка и публичные экраны на 375, 768, 1024 и 1280 точках;
- после выката: `/api/health`, главная, каталог, карточка, сторис, консоль и сеть.

## Двухуровневый откат

1. Контентный: кнопка «Вернуть как было» использует квитанцию задания и не меняет остальные поля сторис. Обложку из кадра менеджер меняет в форме.
2. Релизный: GitHub Actions сохраняет предыдущую `.next`, выполняет health-check и возвращает её при провале. Пользовательские изображения, исходники, `.env` и квитанции заданий остаются на сервере. После успешного выката откат кода — выкат прежнего коммита.

## Drift Lock

Изменение политики кодирования, путей хранения, state machine, публикации, отката, загрузочных API, менеджерского интерфейса, публичного проигрывателя, deploy-процесса или обязательных проверок делает паспорт устаревшим. Требуются повышение версии, новый fingerprint и повтор всего применимого шлюза.
