## Пользовательская задача

Показывать сторисы с изображениями, видео и LIVE-карточками без скрытой загрузки тяжёлого видео в закрытом виджете. При явном открытии сторис видео должно запускаться штатно, а при ошибке пользователь должен получить понятное восстановление.

Работа менеджеров, созданные ими сторисы, медиафайлы, порядок, связи и CTA сохраняются без изменений.

## Владеемая поверхность

- публичный виджет: `components/store/stories-widget.tsx`;
- публичное чтение сторис: `/api/stories` и существующий слой данных;
- совместимость с `/admin/stories` без изменения его модели записи;
- контрактные, адаптивные и recovery-проверки сторис;
- защита code-only выпуска от случайного изменения базы.

## Контракт 0.9.1

1. Разрешение лёгкого превью привязано к точной паре `story.id + mediaUrl`.
2. При смене сторис старое разрешение не может смонтировать видео новой сторис.
3. Проверка размера превью отменяется при смене сторис и учитывает только успешный HEAD-ответ.
4. Закрытый виджет не делает GET/Range-запрос тяжёлого видео свыше 12 МБ.
5. Явно открытая сторис загружает и воспроизводит видео без ожидания HEAD-проверки.
6. Ошибка открытого видео показывает восстановление «Повторить» без бесконечного автоматического цикла.
7. Ошибка закрытого превью тихо возвращает постер и отзывает разрешение текущего медиа.

## Защита выпуска и Drift Lock

Изменение любого из следующих владельцев требует повышения версии паспорта и повторения всех применимых проверок:

- `components/store/stories-widget.tsx`;
- `/api/stories` или слой чтения StoreStory;
- `scripts/validate-store-stories.js`;
- `scripts/validate-browser-stories-responsive.js`;
- `scripts/validate-stories-preview-recovery.js`;
- `scripts/deploy-preflight.js`;
- `scripts/detect-deploy-database-changes.js`;
- `.github/workflows/deploy.yml`.

Для code-only выпуска классификатор обязан вернуть `db_changed=false`; тогда workflow пропускает резервную копию, `prisma db push` и `prisma/data-migrate.ts`. Любое реальное изменение Prisma переводит выпуск на отдельный защищённый путь с обязательной резервной копией.

Защита 0.9.1 считается актуальной только для source fingerprint выше. Любое изменение владельца или обязательной проверки переводит этот паспорт в stale до повторного полного шлюза, живого браузера и новой версии.
