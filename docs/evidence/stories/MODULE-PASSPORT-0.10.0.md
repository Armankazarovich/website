# Паспорт модуля PiloRus Stories / Онлайн-продавец 0.10.0

Module ID: `marketing.store-stories`

Версия кандидата: `0.10.0-beta.1`

Владелец продукта: PiloRus. Владелец контракта переноса: ARAY Production после отдельной нейтрализации и приёмки.

Статус: **LOCAL CANDIDATE**. Этот паспорт не объявляет модуль `READY` до живой канарейки, проверки отката и полного браузерного шлюза на `pilo-rus.ru`.

Предыдущая защищённая версия: `0.9.1`, паспорт `docs/evidence/stories/MODULE-PASSPORT-0.9.1.md`.

Source fingerprint: будет закреплён финальным release receipt после полного шлюза.

## Пользовательская задача

Посетитель открывает короткую сторис или записанное видео онлайн-продавца без пауз, вызванных исходником размером в сотни мегабайт. Менеджер загружает обычный видеофайл или подготавливает уже опубликованное видео, видит понятный статус и может повторить обработку или вернуть оригинал.

`LIVE` в 0.10.0 означает записанное видео онлайн-продавца. Настоящая прямая трансляция, расписание и подключение провайдера в эту версию не входят.

## Состав модуля

- публичный виджет и просмотр: `components/store/stories-widget.tsx`, `components/store/stories-page-client.tsx`;
- менеджерский экран: `/admin/stories`;
- загрузка: `/api/admin/upload`, `/api/admin/upload/chunk`;
- задания: `/api/admin/story-media/jobs/[id]`;
- подготовка и откат существующей сторис: `/api/admin/stories/[id]/media`;
- политика и очередь: `lib/story-media-policy.cjs`, `lib/story-media-jobs.cjs`, `lib/story-media-worker.cjs`;
- условная публикация: `lib/story-media-publish.cjs`;
- клиент загрузки и восстановления: `lib/admin-upload-client.ts`;
- постоянные квитанции заданий: `.story-media-jobs/<uuid>.json`.
- защищённый выпуск: `.github/workflows/deploy.yml`.

## Медиа-контракт 0.10.0

1. Оригинал никогда не перезаписывается и не удаляется обработчиком.
2. Тяжёлый MP4 больше 24 МиБ, MOV и WebM обрабатываются в фоне; совместимый MP4 до 24 МиБ может использоваться напрямую.
3. Web-копия: MP4, H.264, `yuv420p`, AAC 96 кбит/с, до 30 кадров/с, не более 720×1280, CRF 23, ограничение потока 4 Мбит/с, `faststart`.
4. Одновременно работает только один процесс кодирования, чтобы не перегружать VPS.
5. Публикация происходит только после полного декодирования, проверки профиля, уменьшения размера и готовности постера.
6. Для существующей сторис меняется только `mediaUrl`. Заголовок, описание, связи, CTA, просмотры, активность, закрепление и порядок не меняются.
7. Замена условная: если менеджер изменил `mediaUrl` после запуска задания, автоматическая публикация останавливается без перезаписи его работы.
8. После перезапуска приложения незавершённая очередь восстанавливается из квитанции. Уже проверенная web-копия повторно не кодируется.
9. Ошибка не запускает бесконечные автоматические повторы. Менеджер получает безопасное сообщение и явную кнопку `Повторить`.
10. Откат меняет только `mediaUrl` с web-копии на зафиксированный оригинал и также прекращается при конфликте с ручным изменением.

## Файлы и сохранность

- новый тяжёлый исходник: `public/images/stories/originals/<stem>.<ext>`;
- временный результат: `<stem>-web.processing.mp4`;
- проверенный результат: `<stem>-web.mp4`;
- постер: `<stem>-poster.jpg`;
- квитанция и точный откат: `.story-media-jobs/<uuid>.json`;
- `.env`, `public/uploads`, `public/images` и `.story-media-jobs` не удаляются code-only deploy-процессом;
- Prisma-схема, миграции и `data-migrate` в 0.10.0 не меняются.

## Состояния и восстановление

`QUEUED -> PROCESSING -> PUBLISHING -> READY`

Сбой переводит задание в `FAILED`. Разрешён один явный повтор по действию менеджера. Если процесс оборван перезапуском сервера, опрос статуса безопасно возвращает задание в очередь. Временные `.processing`-файлы не публикуются.

## Роли и защищённые действия

- посетитель: просмотр, пауза, звук, навигация, CTA;
- сотрудник: чтение списка сторис по действующим правилам;
- `MANAGER`, `ADMIN`, `SUPER_ADMIN`: создание, подготовка, повтор и откат;
- публикация и откат требуют подтверждения записи и привязаны к текущему `tenantId`;
- произвольные внешние URL и выход за `public/images/stories` для серверной обработки запрещены.

## Зависимости и переносимость

- runtime: Node.js 20, файловая система с постоянным хранилищем, Prisma и FFmpeg;
- бинарник поставляется через точную зависимость `ffmpeg-static@5.3.0`, а не ручную установку на VPS;
- текущий профиль использует `libx264`; перед внешней поставкой или коммерческим распространением бинарника требуется отдельная проверка лицензии GPL и патентных условий H.264;
- модуль пока является клиентским кандидатом PiloRus. Перенос в Zeder или ARAY выполняется только по цепочке `contract tests -> ArmanGlass -> shadow -> canary -> stable`, без копирования дерева проекта и без переноса данных PiloRus.

## Обязательный шлюз

- `npm run stories:media:check` — реальное кодирование, проверка профиля, сохранение оригинала, ошибка, повтор, публикация и откат;
- `npm run stories:check` — контракт и владельцы модуля;
- `npx tsc --noEmit --pretty false`;
- `npm run protection:check`;
- `node scripts/validate-release-readiness.js`;
- `npm run build:ci` без `db push` и без `data-migrate`;
- реальный авторизованный браузер `/admin/stories`: нормальная загрузка, статусы, повтор, подготовка существующей сторис и откат;
- публичный desktop/tablet/mobile: закрытый виджет не загружает тяжёлое видео, открытая сторис получает `206 Partial Content`, видео воспроизводится, CTA и связи сохранены;
- после deploy: `/api/health`, главная, каталог, сторис, консоль и сеть;
- одна тяжёлая сторис — канарейка; вторая тяжёлая сторис не меняется до приёмки первой.

## Версионный шлюз

- `0.10.0-beta.1`: полный локальный кандидат;
- `0.10.0-rc.1`: одна живая тяжёлая канарейка прошла воспроизведение и откат, затем web-копия повторно подключена;
- `1.0.0`: вторая тяжёлая сторис и одна новая менеджерская загрузка прошли полный браузерный путь, известный долг доступности закрыт или явно исключён новым паспортом.

## Двухуровневый откат

1. Контентный: кнопка `Вернуть оригинал` использует квитанцию задания и не меняет остальные поля сторис.
2. Релизный: GitHub Actions сохраняет предыдущую `.next`, выполняет health-check и возвращает её при провале. Пользовательские изображения, исходники, `.env` и квитанции заданий остаются на сервере.

## Drift Lock

Изменение политики кодирования, путей хранения, state machine, публикации, отката, загрузочных API, менеджерского интерфейса, публичного проигрывателя, deploy-процесса или обязательных проверок делает паспорт устаревшим. Требуются повышение версии, новый fingerprint и повтор всего применимого шлюза.

## Известный долг, не скрываемый версией 0.10.0

- настоящий прямой эфир и расписание трансляций не реализованы;
- Escape, focus trap и `aria-dialog` публичного overlay остаются долгом доступности;
- ручная сортировка сторис в `/admin/stories` не реализована;
- распределённая очередь и облачное хранилище потребуются при горизонтальном масштабировании;
- автоматическая очистка старых оригиналов запрещена до отдельной политики хранения и подтверждённого backup/restore.
